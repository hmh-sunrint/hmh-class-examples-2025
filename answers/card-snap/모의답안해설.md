- 시간: 2-3시간 (설명 1시간, 실습 1-2시간)
- 대상: 초보~중급 (HTML/CSS/JS 기초 지식 있는 학생)
- 목표: 3D CSS 애니메이션과 JavaScript 이벤트 처리 학습

## 진행 순서

### 1단계: 프로젝트 소개 (15분)
- 완성된 answer/ 버전 시연
- 학습 목표 설명

### 3단계: CSS 3D 애니메이션 (25분)

- classList 조작 (add/remove)

- 에러 해결 도움
- 개인화 작업 지원
- 추가 도전과제 제시

## 주요 설명 포인트

### CSS Transform 설명할 때
\`\`\`css
/* 이렇게 단계별로 설명 */
.card {
  perspective: 1000px; /* 3D 공간 만들기 */
}
.front {
  transform: rotateY(0deg); /* 기본 상태 */
}
.front.front-visible {
  transform: rotateY(180deg); /* 뒤집힌 상태 */
}
\`\`\`

### JavaScript 이벤트 설명할 때
\`\`\`javascript
// 이벤트 → 상태변경 → DOM조작 순서로 설명
card.addEventListener("click", function(){
  // 1. 상태 확인
  if (count === 1) {
    // 2. DOM 조작
    front.classList.add("front-visible");
  }
});
\`\`\`

## 예상 질문과 답변

**Q: perspective가 뭔가요?**
A: 3D 공간에서 보는 시점을 정하는 거예요. 값이 클수록 멀리서 보는 것처럼 3D 효과가 약해져요.

**Q: 왜 count 변수를 쓰나요?**
A: 카드가 앞면인지 뒷면인지 상태를 기억하기 위해서예요. 클릭할 때마다 상태를 바꿔줘야 하거든요.

**Q: classList.add와 style.display의 차이는?**
A: classList는 CSS 클래스를 조작하고, style.display는 직접 스타일을 바꾸는 거예요. 클래스 방식이 더 깔끔해요.

## 디버깅 가이드

### 자주 발생하는 오류들

**1. 카드가 뒤집히지 않을 때**
- CSS에서 perspective 값 확인
- JavaScript에서 클래스명 오타 확인
- 이벤트 리스너가 제대로 연결되었는지 확인

**2. 애니메이션이 부자연스러울 때**
- transition 시간 조정
- transform-origin 확인
- backface-visibility 설정 확인

**3. 전체화면이 안 될 때**
- 브라우저 호환성 확인
- HTTPS 환경에서 테스트
- 사용자 제스처 후에 호출되는지 확인

### 브라우저별 테스트 포인트
- Chrome: 기본적으로 잘 동작
- Safari: webkit 접두사 필요할 수 있음
- Firefox: moz 접두사 확인
- 모바일: 터치 이벤트 고려
