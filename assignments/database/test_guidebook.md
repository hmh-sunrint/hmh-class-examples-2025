# 📗 Firebase 가이드북 실습 코드 테스트 시나리오

아래 테스트들은 `/database/practice/guidebook.md`의 예제 코드가 정상적으로 동작하는지 확인하기 위한 절차입니다. 각 항목별로 직접 브라우저에서 실행하며 결과를 검증합니다.

---

## 1. Firestore 초기화 테스트

**절차**
- firebaseConfig 객체에 올바른 값(API 키 등)을 입력한다.
- 페이지를 새로고침한다.

**예상 결과**
- 콘솔 에러 없이 Firestore가 정상적으로 초기화된다.

---

## 2. 데이터 추가 (CREATE) 테스트

**절차**
- 이름과 이메일 입력란에 값을 입력한다.
- '추가' 버튼을 클릭한다.

**예상 결과**
- "데이터가 성공적으로 추가되었습니다!" 메시지가 표시된다.
- 입력란이 초기화된다.
- 데이터 목록에 새 항목이 나타난다.

---

## 3. 데이터 조회 (READ) 테스트

**절차**
- 페이지를 새로고침하거나 '조회' 버튼을 클릭한다.

**예상 결과**
- 저장된 모든 데이터가 목록에 표시된다.
- 각 항목에 ID, 이름, 이메일, 생성일이 올바르게 출력된다.

---

## 4. 데이터 수정 (UPDATE) 테스트

**절차**
- 수정할 데이터의 ID, 이름 또는 이메일을 입력한다.
- '수정' 버튼을 클릭한다.

**예상 결과**
- "데이터가 성공적으로 수정되었습니다!" 메시지가 표시된다.
- 데이터 목록에 변경된 내용이 반영된다.

---

## 5. 데이터 삭제 (DELETE) 테스트

**절차**
- 삭제할 데이터의 ID를 입력한다.
- '삭제' 버튼을 클릭한다.
- 확인 창에서 '확인'을 선택한다.

**예상 결과**
- "데이터가 성공적으로 삭제되었습니다!" 메시지가 표시된다.
- 데이터 목록에서 해당 항목이 사라진다.

---

## 6. 메시지 표시 함수 테스트

**절차**
- 각 CRUD 동작 후 메시지 영역을 확인한다.

**예상 결과**
- 성공 시 초록색, 실패 시 빨간색 등 타입에 따라 메시지 스타일이 변경된다.
- 3초 후 메시지가 자동으로 사라진다.

---

## 7. 자동 조회 테스트

**절차**
- 페이지를 새로고침한다.

**예상 결과**
- 데이터 목록이 자동으로 표시된다.

---

## 8. firebaseConfig 보안 테스트

**절차**
- firebaseConfig 객체가 외부에 노출되지 않는지 확인한다.

**예상 결과**
- 콘솔이나 네트워크 탭에서 firebaseConfig 값이 노출되지 않는다.

---

**참고:** 모든 테스트는 실제 Firestore 프로젝트와 연결된 상태에서 진행해야 하며, 각 함수가 정상적으로 동작하는지 UI와 콘솔 로그를 통해 확인합니다.
